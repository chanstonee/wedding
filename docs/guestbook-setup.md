# 무료 방명록 서버 설정 안내

이 안내는 Google Sheets + Google Apps Script 방명록 서버의 설정 절차입니다. 청첩장의 방명록 섹션은 이 서버를 사용합니다. 스프레드시트는 비공개로 유지하고, 웹앱만 익명으로 접속할 수 있게 배포합니다. 하객의 Google 로그인은 필요하지 않습니다.

## 1. 파일 준비

다운로드 묶음의 `apps-script` 폴더에서 아래 파일을 사용하세요.

| 파일 | Apps Script에서 만들 파일 | 역할 |
| --- | --- | --- |
| `Code.gs` | 스크립트 `Code` | 등록·조회·삭제 및 서버 검증 |
| `Bcrypt.gs` | 스크립트 `Bcrypt` | 비밀번호 해시 라이브러리 |
| `Bridge.html` | HTML `Bridge` | 청첩장과 서버의 브라우저 통신 |
| `appsscript.json` | 기존 매니페스트 | V8·한국 시간·시트 접근 권한 |
| `LICENSE.bcryptjs` | 업로드 불필요 | 라이브러리 라이선스 보관용 |

`.gs`와 `.html`은 Google Drive에 업로드하는 것이 아니라, 텍스트 편집기로 열어 전체 내용을 복사해 Apps Script 편집기에 붙여넣습니다. 파일 이름 입력 시 확장자를 중복해서 입력하지 마세요. `Bcrypt.gs`의 라이선스 주석도 그대로 유지하세요. npm 설치는 필요하지 않습니다.

## 2. 비공개 시트 만들기

1. Google 스프레드시트에서 **빈 스프레드시트**를 만듭니다. 이름은 예를 들어 `우리의 청첩장 방명록`으로 정하세요.
2. 오른쪽 위 **공유 → 일반 액세스 → 제한됨**인지 확인합니다. 시트를 웹에 게시하거나 링크가 있는 모든 사용자에게 공유하지 마세요.
3. 시트 내용과 열 이름은 직접 입력하지 않아도 됩니다. 아래 초기화 함수가 `Guestbook` 탭과 필요한 열을 자동 생성합니다. 다른 탭은 건드리지 않습니다.

## 3. Apps Script에 코드 넣기

### 이미 웹앱 URL을 만든 프로젝트가 있는 경우

보내주신 `/exec` URL을 유지하려면 **그 URL을 배포했던 동일한 Apps Script 프로젝트**를 여세요. 기존 프로젝트에 다른 업무 코드가 있다면 별도 복사본에 먼저 보관하고, 방명록 전용 프로젝트인지 확인하세요.

1. `Code.gs`에 준비된 `Code.gs` 전체 내용을 붙여넣습니다. 동일한 함수 이름을 가진 예전 방명록 코드와 중복되지 않게 합니다.
2. 왼쪽 **파일 + → 스크립트**에서 `Bcrypt`를 만들고 `Bcrypt.gs` 내용을 붙여넣습니다.
3. **파일 + → HTML**에서 `Bridge`를 만들고 `Bridge.html` 내용을 붙여넣습니다.
4. **프로젝트 설정 → 편집기에 appsscript.json 매니페스트 파일 표시**를 켭니다. 편집기로 돌아와 `appsscript.json`을 제공한 내용으로 바꿉니다. 이 매니페스트에는 스프레드시트 접근 권한만 있습니다.
5. 프로젝트가 새 시트에 연결되지 않은 독립 프로젝트라면 **프로젝트 설정 → 스크립트 속성 → 스크립트 속성 추가**에서 다음을 설정합니다.

   - 속성: `SPREADSHEET_ID`
   - 값: 시트 주소 `https://docs.google.com/spreadsheets/d/여기가_ID/edit`에서 `/d/`와 `/edit` 사이의 문자열

시트 ID를 공개 코드나 청첩장 환경변수에 넣지 마세요. 프로젝트의 비공개 스크립트 속성에만 넣습니다.

### 아직 Apps Script 프로젝트를 만들지 않은 경우

시트에서 **확장 프로그램 → Apps Script**를 열고 위 1~4단계를 진행합니다. 이 방식은 해당 시트에 연결되므로 `SPREADSHEET_ID`를 직접 넣지 않아도 됩니다. 이미 URL이 있는 경우에는 위의 기존 프로젝트 절차를 사용해야 같은 URL을 유지할 수 있습니다.

## `setTimeout is not defined`가 표시되는 경우

초기 제공본 bcrypt의 타이머 선택 코드에서 발생한 호환성 오류입니다. 최신 묶음의 `Bcrypt.gs` 전체를 기존 파일에 다시 붙여넣어 저장하세요. 스크립트 속성·시트·다른 파일을 초기화할 필요는 없습니다. 그다음 아래 `setupGuestbook_`와 `testGuestbookConnection_`을 실행합니다. 이 수정은 타이머 없는 환경의 로딩만 보완하며 해시 알고리즘이나 기존 데이터는 변경하지 않습니다.

## 편집기 함수 메뉴에 밑줄 함수가 보이지 않는 경우

`Code.gs` 맨 아래에 다음 두 함수를 임시로 추가해 저장하면 메뉴에서 `runSetupGuestbook`, `runTestGuestbookConnection`을 선택할 수 있습니다. 아래 4~5단계의 원래 함수 대신 각각 실행합니다.

```js
function runSetupGuestbook() { return setupGuestbook_(); }
function runTestGuestbookConnection() { return testGuestbookConnection_(); }
```

**실제 점검을 마친 뒤 웹앱 새 버전 배포 전에는 두 임시 함수를 삭제하세요.** 원래 밑줄로 끝나는 함수는 유지합니다. 임시 공개 함수가 배포된 브리지에서 호출될 수 없도록 정리하는 단계입니다. 이미 실행용 함수를 `runSetupGuestbook_`, `runTestGuestbookConnection_`으로 바꿨다면 비공개 이름이므로 유지해도 됩니다.

## 4. 초기화와 Google 권한 승인

1. 모든 파일을 저장합니다.
2. 편집기 위쪽 함수 선택에서 **`setupGuestbook_`**를 선택하고 **실행**합니다. 끝의 밑줄까지 포함한 이름입니다. 이 함수는 편집기에서 소유자가 실행하며 웹 RPC에서는 호출할 수 없습니다.
3. 처음에는 Google 권한 승인이 나옵니다. 본인이 만든 프로젝트인지, 요청 권한이 Google 스프레드시트 접근인지 확인하고 본인의 계정으로 승인합니다. 자체 스크립트이므로 미확인 앱 안내가 나올 수 있습니다. 다른 사람이 만든 프로젝트나 예상과 다른 권한이면 승인하지 마세요.
4. 시트에 `Guestbook` 탭과 8개 열이 생겼는지 확인합니다.

`PRIVATE_PEPPER`와 `ALLOWED_ORIGINS`는 자동 설정됩니다. 비밀값을 직접 생성하거나 전달할 필요가 없습니다. **`PRIVATE_PEPPER`를 삭제·변경하면 기존 비밀번호를 검증할 수 없으므로 그대로 유지하세요.** 초기화는 다시 실행해도 기존 비밀값과 메시지를 보존합니다. 열 구성이 다르면 덮어쓰지 않고 중단합니다.

기본 허용 출처는 `https://chanstonee.github.io`입니다. 출처에는 `/wedding/` 같은 경로를 붙이지 않습니다.

## 5. 실제 시트 저장 자체 점검

함수 선택에서 **`testGuestbookConnection_` → 실행**합니다. 이 함수는 실제 시트에 임시 메시지 한 건을 등록하고 조회·잘못된 비밀번호 거절·올바른 비밀번호 삭제를 확인합니다. 자신이 만든 테스트 행만 정리하며 기존 메시지를 삭제하지 않습니다.

실행 로그에 다음 항목이 모두 `true`이면 서버의 실제 시트 저장 점검이 통과한 것입니다.

```json
{"created":true,"read":true,"wrongPasswordBlocked":true,"deleted":true,"completed":true,"elapsedMs":12345}
```

`elapsedMs`는 실행마다 달라집니다. bcrypt 비용 12를 사용하므로 처음 실행은 잠시 걸릴 수 있습니다. `완료`만 보고 성공으로 판단하지 말고 위 항목을 확인하세요. 오류가 나면 오류 코드와 실행 단계만 전달하고 비밀번호·해시·스크립트 속성은 공유하지 마세요.

이 점검은 **시트와 서버 사이의 검증**입니다. GitHub Pages 브라우저 연결은 다음 배포 후 별도로 확인해야 합니다.

## 6. 웹앱 배포 또는 기존 URL 업데이트

이미 보내주신 URL이 있으므로 일반적으로 **기존 배포 업데이트**를 사용하세요.

1. 오른쪽 위 **배포 → 배포 관리**를 엽니다.
2. 기존 웹앱 배포 선택 → **수정(연필)**을 누릅니다.
3. 버전에서 **새 버전**을 선택합니다. 코드 저장만으로는 `/exec` 배포본이 업데이트되지 않습니다.
4. **실행 사용자: 나(시트 소유자)**를 선택합니다.
5. **액세스 권한: 모든 사용자(Anyone)**를 선택합니다. `Google 계정이 있는 모든 사용자`는 하객 로그인 없이 사용하려는 조건과 다릅니다.
6. **배포**를 누릅니다. 기존 배포를 수정하면 일반적으로 같은 `/exec` URL을 유지합니다.

처음 만드는 프로젝트라면 **배포 → 새 배포 → 유형 선택 → 웹 앱**에서 같은 설정으로 배포합니다. `/dev`는 편집자 테스트용이므로 전달하지 마세요.

회사·학교 계정에서 익명 `모든 사용자` 옵션을 금지했다면 관리자 정책을 우회하지 마세요. 해당 정책이 없는 개인 Google 계정으로 무료 구성이 가능한지 확인해야 합니다.

## 7. 배포 후 전달할 내용

1. Google에 로그인하지 않은 시크릿 창에서 `/exec` URL을 엽니다.
2. `방명록 웹앱이 열렸습니다.` 안내가 나오고 로그인 요구가 없는지 확인합니다. 이 화면에는 실제 메시지나 비밀값이 나오지 않습니다.
3. **새 버전 배포 완료 여부**와 5단계 로그의 성공 여부를 알려주세요. 이미 제공한 URL을 유지했다면 다시 보낼 필요가 없습니다. URL이 바뀐 경우에만 새 `/exec` URL을 전달해 주세요.

그다음 청첩장 연결 단계에서 실제 GitHub Pages 출처의 등록·조회·삭제, 독립 브라우저 조회, 통신 및 모바일 화면을 검증합니다. 실제 저장과 브라우저 연결이 확인되기 전에는 완성이나 배포 성공으로 보고하지 않습니다.

## 무료 운영과 한계

Google 계정의 무료 Apps Script·Sheets 할당량을 사용하는 구성입니다. 유료 데이터베이스, Supabase, 결제 API는 사용하지 않습니다. 별도 과금 서비스를 연결하지 않았으며 무료 할당량 초과 시에는 실행이 제한되거나 중단될 수 있습니다. 무제한 운영이나 무중단을 보장하지 않습니다.

메시지는 사용자가 비밀번호로 삭제하거나 소유자가 직접 삭제하기 전까지 시트에 저장됩니다. 자동 만료는 없습니다. 시트는 계속 비공개여야 하지만 방명록 **이름·메시지·작성일은 청첩장 방문자에게 공개**됩니다. 민감한 개인정보를 쓰지 않도록 안내하는 것이 좋습니다.

상세한 저장 구조·스팸 제한·브라우저 제약과 검증 결과는 [기술 문서](guestbook-technical.md)를 참고하세요.
